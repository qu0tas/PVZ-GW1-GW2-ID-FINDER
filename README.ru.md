## ✨ Что это умеет

| Вкладка | Для чего |
| :-- | :-- |
| **Поиск ID** | Есть хеш вроде `081816D8`, нужна строка, которая его даёт. Решается алгеброй мгновенно. |
| **База хешей** | 31 486 известных хешей, вытащенных из GW1 и GW2 через Frosty Editor. Поиск по хешу и по тексту, фильтр по длине, сортировка, постраничный вывод. |
| **Проверка строки** | Обратное направление: вводишь любую строку, сразу видишь её хеш и то, привязано ли к нему что-то в игре. |

Русский и английский языки с переключением в любой момент. Язык, игра, вкладка и запрос переживают перезагрузку и попадают в адрес страницы.

## 🗂 Базы

| Файл | Записей | Размер |
| :-- | --: | --: |
| `data/gw1.json` | 8 062 | 353 КБ |
| `data/gw2.json` | 23 424 | 964 КБ |

Формат нарочно скучный — хеш в значение, отсортировано по хешу, чтобы diff оставался читаемым:

```json
{
  "081816D8": "{(C)PRESENCE_CONTEXT_GAMEMODE_ROUND_NAME}",
  "0815FE6E": "Law Pea"
}
```

> [!TIP]
> Таблица явно сортируется при загрузке, а не полагается на порядок ключей. JavaScript выдаёт ключи, похожие на индексы массива (`"10067901"`), первыми и в числовом порядке — именно поэтому без сортировки список начинался с середины.

### Как обновить

Из свежего CSV-дампа Frosty (UTF-16 или UTF-8, с BOM или без, кавычки по RFC-4180):

```bash
node tools/import-csv.mjs GW1HASH.csv GW2HASH.csv
```

Из старой однофайловой сборки, где базы вшиты в `index.html`:

```bash
node tools/extract-db.mjs путь/к/old-index.html
```

Оба скрипта приводят хеши к 8 заглавным hex-символам, отбрасывают битые строки, схлопывают дубли и отчитываются о сделанном.

## 🧮 Хеш-функция

Garden Warfare использует обычный DJB2-подобный хеш с начальным значением `0xFFFFFFFF`
(`FsLocalizationStringDatabase.HashStringId`):

```
h = 0xFFFFFFFF
для каждого БАЙТА c строки:
    h = (h * 33 + c) mod 2^32
```

Две ловушки, которые в JavaScript тихо дают неверный результат:

> [!WARNING]
> **`h * 33` небезопасно.** Когда `h` становится полноценным 32-битным, произведение превышает `2^53`, и число с плавающей точкой молча теряет младшие биты. `Math.imul(h, 33)` — настоящее 32-битное умножение и единственный корректный вариант.

> [!WARNING]
> **Хешируются байты, а не символы.** `charCodeAt` возвращает UTF-16 code units и расходится с игрой на всём, что не ASCII. `TextEncoder` даёт те самые байты UTF-8, которые видит движок.

Оба момента проверяются самотестом против эталонной реализации на `BigInt`.

## ⚡ Обращение хеша

Этот хеш **не** является односторонней функцией. Это линейный многочлен над `ℤ/2³²`, то есть его можно решить напрямую. Доступны два режима.

### Алгебра — режим по умолчанию

Для префикса `P` и `n` неизвестных символов после него:

```
target = 33ⁿ · H(P) + c₀·33ⁿ⁻¹ + c₁·33ⁿ⁻² + … + cₙ₋₁   (mod 2³²)
```

Переносим известную часть влево и вычитаем базу, которую дают все символы (каждый записывается как `65 + d`, где `d` от 0 до 32):

```
X = (target − 33ⁿ · H(P))            mod 2³²
G = 33⁰ + 33¹ + … + 33ⁿ⁻¹ = (33ⁿ − 1) / 32
D = (X − 65·G)                       mod 2³²
```

Оставшееся `D` — это ��овно запись числа в системе с основанием 33. Считываем `n` разрядов, каждый переводим в символ `65 + d` — никакого перебора вообще.

При `n = 7` имеем `33⁷ = 42 618 442 977 > 2³²`, значит **достижим любой хеш**.

Одна деталь, которую стоит использовать: `D` известно лишь по модулю `2³²`, и любое `D + k·2³²`, которое всё ещё влезает в 7 разрядов по основанию 33, — тоже верный ответ. Поскольку `33⁷` больше `2³²` в 9,9 раза, это даёт до **10 разных решений на один префикс бесплатно**. Остальные получаются добивкой префикса (`ID_A`, `ID_B`, …) и повторным решением.

**1000 полных решений занимают около 66 мс**, по 30–40 вариантов на каждое.

### Встреча посередине — когда нужен конкретный алфавит

Перебор остался на случай, когда ответ должен состоять из определённых символов (только hex, только цифры и так далее). Разбиваем хвост на половины `A` и `B`:

```
H(prefix + A + B) = H(prefix + A) · 33^|B| + Q(B)   (mod 2³²)
```

Строим таблицу левой части для всех `A`, потом прогоняем все `B` и проверяем по ней. Это превращает `|алфавит|^L` примерно в `2 · |алфавит|^(L/2)` — для hex-хвоста длиной 8 это **131 072 кандидата вместо 4 294 967 296**.

| Пресет | Длины | Кандидатов | Время |
| :-- | :-- | --: | --: |
| быстро | 8 | 131 072 | ~30 мс |
| стандарт | 4–9 | 1 327 872 | ~50 мс |
| тщательно | 1–10 | 3 425 345 | ~70 мс |

> [!NOTE]
> Перебор вполне законно может не найти ничего. `16⁸` кандидатов на `2³²` исходов означают, что примерно у **37% хешей вообще нет прообраза вида `ID_` + 8 hex-символов**. У алгебры такой проблемы нет — поэтому она и стоит по умолчанию.

Детали реализации:

- Таблица поиска — открытая хеш-таблица на плоских `Uint32Array` / `Int32Array` с цепочками, а не JS-объект со строковыми ключами. Никакого давления на GC и рехеширования, дубли ключей обрабатываются корректно.
- Половины генерируются итеративно по принципу одометра, без рекурсии.
- Перебор работает в **Web Worker**, поэтому страница не виснет, а кнопка **Стоп** действительно останавливает. Прогресс настоящий, около 20 обновлений в секунду.
- Длины, чьи половины не влезают в лимит памяти (`MAX_HALF = 2²²`), пропускаются с пояснением в строке статуса, а не вешают вкладку.
- **Любой результат обоих режимов перепроверяется** полной хеш-функцией перед показом. Ошибка в арифметике никогда не даст неверный ответ — только пропущенный.

## ⚠ Коллизии — прочтите

У 32-битного хеша всего 4,3 миллиарда возможных значений, так что коллизии — не редкость, а норма. У типичного хеша есть **десятки** прообразов вида `ID_`.

Каждая возвращённая строка действительно даёт нужный хеш. Но почти наверняка это **не** та строка, которую написали разработчики.

Поэтому, если целевой хеш есть в базе GW1/GW2, реальное привязанное значение показывается **над** результатами. Обычно именно эта строка и нужна, а сгенерированные `ID_` полезны только тогда, когда привязки нет.

## 📁 Структура проекта

```
index.html               только разметка — ни стилей, ни логики, ни данных
css/style.css            всё оформление, один файл
js/
  hash.js                хеш-функция (Math.imul + байты UTF-8)
  algebra.js             прямое алгебраическое решение — режим по умолчанию
  search-core.js         перебор встречей посередине — чистый, без DOM
  search-worker.js       запускает search-core вне главного потока
  database.js            ленивая загрузка, фильтрация, сортировка
  finder.js              вкладка поиска ID
  db-view.js             вкладка базы хешей
  checker.js             вкладка проверки строки
  i18n.js                все строки интерфейса, RU + EN
  util.js                хелперы DOM, буфера обмена и состояния в URL
  main.js                запуск, вкладки, клавиатура, сохранение состояния
data/                    gw1.json, gw2.json
tools/
  import-csv.mjs         CSV из Frosty -> data/*.json
  extract-db.mjs         старый index.html со вшитыми базами -> data/*.json
  selftest.mjs           корректность и замеры скорости
  algebra-check.mjs      алгебра против перебора против эталона на BigInt
  make-sample-data.mjs   тестовые данные для разработки
  qa-shots.mjs           скриншоты всех экранов в headless-браузере
```

Ничто не импортирует лишнего, а `search-core.js` и `algebra.js` вообще не зависят от DOM — именно поэтому их можно тестировать в Node и переиспользовать в воркере.

## 🧪 Тесты

```bash
node tools/selftest.mjs
```

Хеш против эталона на `BigInt` (включая пустые строки, строки по 300 символов и кириллицу), `pow33`, разбор ввода, обратный ход поиска, крайний случай `длина = 1` с пустой половиной, нечётные разбиения, пустые префиксы, большие алфавиты, лимиты результатов и пропуск по памяти. Каждый кандидат перехешируется и проверяется.

```bash
node tools/algebra-check.mjs
```

Сверяет три независимые реализации друг с другом: буквальную транскрипцию игровой функции на `BigInt`, рабочий `hash.js` и оба режима обращения. Подтверждает, что `n = 7` достигает любого хеша на 20 000 случайных целях, и проверяет порядок ключей в базах.

```bash
node tools/qa-shots.mjs   # нужен локальный сервер на :8124 и Playwright
```

Рисует 11 экранов на ширине 1280 и 390 пикселей и падает при любой ошибке в консоли.

## ⌨ Горячие клавиши и ссылки

| Клавиша | Действие |
| :-- | :-- |
| `/` | Фокус на поле поиска текущей вкладки |
| `Esc` | Остановить идущий поиск |
| `←` `→` `Home` `End` | Переключение между вкладками |

Состояние живёт в адресной строке, так что любым экраном можно поделиться:

```
?tab=finder&hash=081816D8
?tab=db&game=gw2&q=peashooter
?lang=en
```

Любой строковый ID во Frostbite начинается с `ID_`, поэтому префикс зафиксирован и отдельного поля под него нет. Для редкого случая, когда нужно хешировать не строковый ID, его можно подменить через `?prefix=SOMETHING_`.

## 🌐 Поддержка браузеров

Chrome, Edge, Firefox и Safari, на компьютере и на телефоне. Нужны ES-модули, `Math.imul`, `TextEncoder` и модульные Web Workers — всё это появилось ещё до 2023 года. Если воркеры недоступны, перебор прозрачно переключается на порционное выполнение в главном потоке.

Полностью адаптивный интерфейс: на телефоне настройки выстраиваются в две колонки, цели касания по 44 пикселя, шапка таблицы прилипает при скролле, учтены безопасные зоны под чёлку, нет зума при фокусе на поле и уважается `prefers-reduced-motion`.
